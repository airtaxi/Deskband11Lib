Host your own UI inside the Windows 11 taskbar Windows 11 작업 표시줄 안에 직접 만든 UI를 띄워 보세요

Deskband11Lib parents your window to the taskbar and fits it into the free space between the app buttons and the notification area. Use it for timers, media controls, build status, or anything else that should stay in view without opening a window. Packages are available for .NET, Python, Node.js, and Rust.

Deskband11Lib는 앱 창을 작업 표시줄의 자식 창으로 붙이고, 앱 버튼과 알림 영역 사이에 남는 공간에 맞춰 크기를 조정합니다. 타이머, 미디어 컨트롤, 빌드 상태처럼 별도 창을 열지 않고도 늘 보여야 하는 기능에 활용할 수 있습니다. 패키지는 .NET, Python, Node.js, Rust용으로 제공됩니다.

dotnet add package Deskband11Lib.WinUI

Placement배치

UI Automation locates the Start button, the app buttons, the Widgets button, and the notification area. Content goes into one of the free gaps between them, chosen by the Placement option and the taskbar alignment, which is read from the TaskbarAl registry value.

UI Automation으로 시작 버튼, 앱 버튼, 위젯 버튼, 알림 영역의 위치를 찾습니다. 콘텐츠는 그 사이에 남는 공간 중 한 곳에 배치되며, 어느 공간을 쓸지는 Placement 옵션과 작업 표시줄 정렬에 따라 정해집니다. 작업 표시줄 정렬은 레지스트리의 TaskbarAl 값에서 읽습니다.

Quick start시작하기

Create a window, pass it and its root element to TaskbarContentHost, then attach it once the taskbar layout is ready. WinUI 3 and WPF share the same API; only the Window and FrameworkElement types come from different namespaces.

창을 만든 다음 창과 루트 요소를 TaskbarContentHost에 넘기고, 작업 표시줄 레이아웃이 준비되면 창을 붙입니다. WinUI 3와 WPF는 같은 API를 사용하며, Window와 FrameworkElement 타입의 네임스페이스만 다릅니다.

The snippets show the shape of the API. For window lifetime, startup order, and framework-specific hosting, start from the WinUI 3 sample or the WPF sample, which also sets up a transparent borderless host window.

위 코드는 API의 형태만 보여 줍니다. 창 수명 주기, 시작 순서, 프레임워크별 호스팅 처리는 WinUI 3 샘플이나 WPF 샘플에서 시작하시는 것을 권장합니다. WPF 샘플에는 테두리 없는 투명 호스트 창 설정도 들어 있습니다.

QtTaskbarWidgetController creates your widget through a factory, removes its frame, attaches it to the taskbar, and shows it once it is in place. It works with PySide6 and PyQt6, and TaskbarContentHost hosts a window from any other toolkit by its handle.

QtTaskbarWidgetController는 팩토리로 위젯을 만들고 창 테두리를 없앤 뒤 작업 표시줄에 붙이며, 자리를 잡으면 위젯을 표시합니다. PySide6와 PyQt6에서 사용할 수 있고, 다른 툴킷의 창은 TaskbarContentHost에 창 핸들을 넘겨 호스팅할 수 있습니다.

For a complete widget that follows the taskbar theme and switches between horizontal and vertical layouts, start from the PySide6 clock sample. Hosting windows from other toolkits, events, and options are covered in the package README.

작업 표시줄 테마를 따라가고 가로와 세로 레이아웃을 전환하는 완성된 위젯은 PySide6 시계 샘플에서 확인할 수 있습니다. 다른 툴킷의 창을 호스팅하는 방법과 이벤트, 옵션은 패키지 README에 정리되어 있습니다.

ElectronTaskbarWindowController creates your BrowserWindow through a factory, attaches it to the taskbar, and creates it again whenever the taskbar requires it. Use it from the main process; createTaskbarWindowOptions() adds the window settings a taskbar window needs.

ElectronTaskbarWindowController는 팩토리로 BrowserWindow를 만들어 작업 표시줄에 붙이고, 작업 표시줄이 요구할 때마다 창을 다시 만듭니다. 메인 프로세스에서 사용하며, createTaskbarWindowOptions()가 작업 표시줄 창에 필요한 창 설정을 채워 줍니다.

For a complete widget that follows the taskbar theme and switches between horizontal and vertical layouts, start from the Electron clock sample. Packaging with asar and hosting a window by its handle are covered in the package README.

작업 표시줄 테마를 따라가고 가로와 세로 레이아웃을 전환하는 완성된 위젯은 Electron 시계 샘플에서 확인할 수 있습니다. asar로 패키징하는 방법과 창 핸들로 직접 호스팅하는 방법은 패키지 README에 정리되어 있습니다.

Register the plugin, then start a TaskbarWindowController from the setup hook. taskbar_window_builder() returns a webview window builder with the settings a taskbar window needs, and the controller creates the window again whenever the taskbar requires it.

플러그인을 등록한 뒤 setup 훅에서 TaskbarWindowController를 시작합니다. taskbar_window_builder()는 작업 표시줄 창에 필요한 설정이 들어간 웹뷰 창 빌더를 돌려주고, 컨트롤러는 작업 표시줄이 요구할 때마다 창을 다시 만듭니다.

For a complete widget that follows the taskbar theme and switches between horizontal and vertical layouts, start from the Tauri clock sample. Bundling deskband11lib.dll into the installer and listening to taskbar events in the frontend are covered in the plugin README. Rust apps without Tauri can use the deskband11lib crate.

작업 표시줄 테마를 따라가고 가로와 세로 레이아웃을 전환하는 완성된 위젯은 Tauri 시계 샘플에서 확인할 수 있습니다. 설치 파일에 deskband11lib.dll을 포함하는 방법과 프런트엔드에서 작업 표시줄 이벤트를 받는 방법은 플러그인 README에 정리되어 있습니다. Tauri를 쓰지 않는 Rust 앱은 deskband11lib 크레이트를 사용하면 됩니다.

using Deskband11Lib.Core;
using Deskband11Lib.WinUI;

var window = new MainWindow();
var host = new TaskbarContentHost(window, rootElement, new TaskbarContentHostOptions
{
    PreferredWidth = 360,
    PreferredHeight = 48
});

await host.AttachWhenLayoutReadyAsync();
window.Activate();

    ElectronTaskbarWindowController,

app.whenReady().then(() => {
    const controller = new ElectronTaskbarWindowController(() => {
        const window = new BrowserWindow(createTaskbarWindowOptions({
            transparent: true,
            backgroundColor: '#00000000',
        }));
        window.loadFile('widget.html');
        return window;
    }, { preferredWidth: 360, preferredHeight: 48 });

    controller.start();
});
use tauri::WebviewUrl;
use tauri_plugin_deskband11lib::{
    TaskbarContentHostOptions, TaskbarWindowController, taskbar_window_builder,
};

tauri::Builder::default()
    .plugin(tauri_plugin_deskband11lib::init())
    .setup(|app| {
        TaskbarWindowController::new(app.handle(), |app| {
            let url = WebviewUrl::App("index.html".into());
            taskbar_window_builder(app, "widget", url)
                .transparent(true)
                .build()
        })
        .options(TaskbarContentHostOptions {
            preferred_width: Some(360.0),
            preferred_height: Some(48.0),
            ..Default::default()
        })
        .start()?;
        Ok(())
    })
    .run(tauri::generate_context!())
    .expect("The application failed to run.");

Recreate the window when the taskbar drops it창이 사라지면 다시 만들기

An Explorer restart, a disconnected monitor, or a DPI change can destroy the hosted window or leave it misaligned. Handle TaskbarWindowRecreationRequired, build a new window, and attach a new host. The Qt, Electron, and Tauri controllers do this for you.

Explorer가 재시작되거나, 모니터 연결이 끊기거나, DPI가 바뀌면 호스팅된 창이 사라지거나 위치가 어긋날 수 있습니다. TaskbarWindowRecreationRequired 이벤트에서 창을 새로 만들고 새 호스트를 붙이면 됩니다. Qt, Electron, Tauri용 컨트롤러는 이 과정을 자동으로 처리합니다.

host.TaskbarWindowRecreationRequired += async (_, _) => await RecreateMainWindowAsync();
Event이벤트 Raised when발생 시점
TaskbarWindowRecreationRequired Any of the cases below. One handler is enough for most apps.아래 모든 경우에 발생합니다. 대부분의 앱은 이 핸들러 하나로 충분합니다.
TaskbarWindowRecreated Explorer restarted, or a disconnected monitor came back.Explorer가 재시작되었거나, 연결이 끊겼던 모니터가 다시 연결되었습니다.
TaskbarDpiChanged The taskbar moved to a new DPI. The library hides and detaches the old window first.작업 표시줄의 DPI가 바뀌었습니다. 라이브러리가 기존 창을 먼저 숨기고 분리합니다.
TaskbarWindowDisappeared The monitor hosting the widget was disconnected. The new host uses the primary taskbar until that monitor returns.위젯을 붙여 둔 모니터의 연결이 끊겼습니다. 그 모니터가 다시 연결될 때까지 새 호스트는 기본 작업 표시줄을 사용합니다.

Several instances in one area한 영역을 나눠 쓰는 여러 인스턴스

Instances that target the same area on the same monitor coordinate through a shared-memory slot registry and split the space without overlapping. Fixed instances, with a finite PreferredWidth, are served first in ManualSlotPriority order, then in arrival order. Stretch instances, with PreferredWidth = double.MaxValue, share whatever is left.

같은 모니터의 같은 영역을 대상으로 하는 인스턴스들은 공유 메모리 슬롯 레지스트리로 서로 조정하여 겹치지 않게 공간을 나눕니다. PreferredWidth가 유한한 Fixed 인스턴스가 ManualSlotPriority 순서, 그다음 도착 순서에 따라 먼저 너비를 받고, PreferredWidth = double.MaxValue인 Stretch 인스턴스들은 남은 공간을 똑같이 나눕니다.

Instance인스턴스 Mode방식 PreferredWidth ManualSlotPriority Allocated할당된 너비

Example instances using BeforeNotificationArea, started in the order Media, Build status, Timer. The first slot in order sits next to the notification area. Widths are effective pixels at 100% scaling.

미디어, 빌드 상태, 타이머 순서로 시작한 예시 인스턴스이며, 모두 BeforeNotificationArea를 사용합니다. 순서상 첫 번째 슬롯이 알림 영역 바로 옆에 놓입니다. 너비는 배율 100% 기준의 effective pixel입니다.

Options옵션

All options live in Deskband11Lib.Core.TaskbarContentHostOptions and work the same in every package. The Python, Node.js, and Rust packages follow the naming style of their language, such as preferred_width in Python and Rust and preferredWidth in Node.js.

모든 옵션은 Deskband11Lib.Core.TaskbarContentHostOptions에 정의되어 있으며, 어느 패키지에서든 똑같이 동작합니다. Python, Node.js, Rust 패키지는 각 언어의 명명 규칙을 따르므로, 예를 들어 PreferredWidth는 Python과 Rust에서 preferred_width, Node.js에서 preferredWidth입니다.

Option옵션 Default기본값 Description설명
PreferredWidth 360 Content length along the taskbar in effective pixels: the width on a bottom or top taskbar, the height on a left or right taskbar. double.MaxValue makes the instance Stretch.작업 표시줄을 따라가는 방향의 콘텐츠 길이입니다(effective pixel). 아래쪽이나 위쪽 작업 표시줄에서는 너비, 왼쪽이나 오른쪽 작업 표시줄에서는 높이입니다. double.MaxValue로 설정하면 Stretch 인스턴스가 됩니다.
PreferredHeight 48 Content size across the taskbar in effective pixels: the height on a bottom or top taskbar, the width on a left or right taskbar. Capped by the taskbar thickness; double.MaxValue fills it.작업 표시줄을 가로지르는 방향의 콘텐츠 크기입니다(effective pixel). 아래쪽이나 위쪽 작업 표시줄에서는 높이, 왼쪽이나 오른쪽 작업 표시줄에서는 너비입니다. 작업 표시줄 두께를 넘지 않으며, double.MaxValue로 설정하면 두께를 꽉 채웁니다.
Placement Auto Which free gap the content goes into: Auto, LeftEdge, BeforeStartButton, or BeforeNotificationArea. See Placement.콘텐츠를 배치할 공간을 고릅니다. Auto, LeftEdge, BeforeStartButton, BeforeNotificationArea 중 하나이며, 자세한 내용은 배치 항목에서 확인할 수 있습니다.
PreferredMonitorIdentity 0 0 uses the primary taskbar. 1 and up pick secondary taskbars from left to right, falling back to the primary taskbar when that monitor is missing.0이면 기본 작업 표시줄을 사용합니다. 1부터는 화면 왼쪽부터 순서대로 보조 모니터의 작업 표시줄을 고르며, 해당 모니터가 없으면 기본 작업 표시줄로 돌아갑니다.
ManualSlotPriority 65535 Order among instances in the same area. Lower values come first; equal values keep arrival order.같은 영역에 있는 인스턴스 사이의 순서를 정합니다. 값이 낮을수록 앞에 오고, 값이 같으면 도착 순서를 따릅니다.
AllowFixedSlotResize true When space runs short, Fixed instances shrink in proportion to their PreferredWidth instead of dropping to zero.공간이 부족할 때 Fixed 인스턴스가 0까지 줄어드는 대신 PreferredWidth 비율에 맞춰 줄어듭니다.
AnimateLayoutChanges true Animates position and size changes.위치와 크기가 바뀔 때 애니메이션을 적용합니다.
LayoutAnimationDuration 500 Layout animation duration in milliseconds.레이아웃 애니메이션 시간입니다(밀리초).
LayoutAnimationEasing EasingFunctions.CircleOut Any Func<double, double>. EasingFunctions provides Linear and the Sine, Quadratic, Cubic, Quartic, Quintic, Exponential, and Circle families in In, Out, and InOut forms. The Python, Node.js, and Rust packages take one of these built-in functions.Func<double, double> 형식이면 무엇이든 사용할 수 있습니다. EasingFunctions에는 Linear와 함께 Sine, Quadratic, Cubic, Quartic, Quintic, Exponential, Circle 계열의 In, Out, InOut 함수가 들어 있습니다. Python, Node.js, Rust 패키지에서는 이 기본 제공 함수 중 하나를 고릅니다.
HighRefreshRateMode true While AnimateLayoutChanges is on, matches the animation timer to the monitor’s current refresh rate. false keeps it at 60 FPS.AnimateLayoutChanges가 켜져 있는 동안 애니메이션 타이머를 모니터의 현재 주사율에 맞춥니다. false로 설정하면 60 FPS로 동작합니다.
TrackTaskbarButtons true Measures the taskbar buttons with UI Automation.UI Automation으로 작업 표시줄 버튼 영역을 측정합니다.

Packages and requirements패키지와 요구 사항

  • Windows 11. The Python, Node.js, and Rust packages include the native library for x64 and ARM64.
  • .NET 10 for the NuGet packages, which target net10.0-windows10.0.26100.0. WinUI 3 apps need the Windows App SDK.
  • Python 3.10 or later.
  • Node.js 22 or later. In Electron, use the package from the main process.
  • Rust 1.90 or later. The Tauri plugin needs Tauri 2.12 or later.
  • Windows 11이 필요합니다. Python, Node.js, Rust 패키지에는 x64용과 ARM64용 네이티브 라이브러리가 들어 있습니다.

  • Python 패키지는 Python 3.10 이상이 필요합니다.
  • Node.js 패키지는 Node.js 22 이상이 필요합니다. Electron에서는 메인 프로세스에서 사용합니다.
  • Rust 크레이트는 Rust 1.90 이상이 필요합니다. Tauri 플러그인은 Tauri 2.12 이상이 필요합니다.
